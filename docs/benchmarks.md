## Рішення: порядок байтів RGB565

`framebuf.RGB565` на ESP32 (і на unix-порті) зберігає пікселі little-endian, ST7789 чекає big-endian.

**Вибрано варіант (а): кольори вже з переставленими байтами («wire order»).**
Генератор і runtime передають кольори як `swap16(rgb565)` (`ui_st7789.color(r, g, b)`), тому буфер `framebuf`,
залитий таким кольором, уже має байти в порядку дисплея й іде в SPI як є.

- Перестановка коштує нуль під час роботи: лише константи в згенерованому коді.
- Не потрібен `@micropython.viper` (на деяких збірках MicroPython, наприклад unix-порті з Homebrew для macOS arm64, native-емітера немає).
- `fill_rect` приймає колір у тому самому вигляді; адаптер `st7789py` переставляє байти назад, бо цей драйвер пакує колір big-endian сам.
- Перевірено тестами (`tests/mpy/test_driver.py`): справжній `framebuf` на unix-порті + фейковий SPI → на шину йде `F8 00` для червоного.

## Відмінності драйверів, які враховує адаптер

| | `builtin` | `st7789py` |
|---|---|---|
| Порядок кольорів | RGB | за замовчуванням BGR → адаптер передає `color_order=RGB` |
| Інверсія | параметр `invert` | у послідовності ініціалізації завжди INVON → `inversion_mode(False)`, якщо треба |
| Вікно поза екраном | `ValueError` | мовчки пропускає CASET/RASET і пише дані в попереднє вікно → адаптер перевіряє межі сам |
| Заливка | смуги по 4096 Б, один CS на всю область, без алокацій | шматки по 512 Б, CS перемикається на кожен шматок |
| `blit` | вікно + буфер в одній транзакції CS | вікно + буфер одним `spi.write` |
| Піни | `.value()` | `.on()/.off()/.value()` — обидва працюють з `machine.Pin` |

## Розрахункові межі (лише час на шині SPI)

| Операція | Байт | 40 МГц | 80 МГц |
|---|---|---|---|
| Заливка екрана 240×320 | 153 600 | 30,7 мс | 15,4 мс |
| `blit` 150×48 | 14 400 | 2,9 мс | 1,4 мс |
| `blit` 32×32 | 2 048 | 0,4 мс | 0,2 мс |

80 МГц на ESP32-S3 можливі лише на пінах IOMUX для SPI2: SCK=12, MOSI=11, CS=10, і саме вони стоять у `docs/hardware.md`.
Через GPIO-матрицю частота обмежена, фактичну видно у стовпці «Фактично» (`print(spi)`).

## Методика

```sh
mpremote cp src/espui/generators/micropython/runtime/ui_display.py \
            src/espui/generators/micropython/runtime/ui_st7789.py \
            src/espui/generators/micropython/runtime/st7789py.py :
mpremote run tools/hw_driver_check.py   # візуально: 2 драйвери × 4 rotation
mpremote run tools/bench_display.py     # заміри
```

- Піни й SPI беруться з `ui_display.py` на платі (ті самі, що в `docs/hardware.md`).
- Час — середнє з 5–20 запусків після прогріву (`time.ticks_us`).
- «Імпорт» — зменшення `gc.mem_free()` після імпорту модуля драйвера.
- Без PSRAM: та сама плата з прошивкою без SPIRAM або модуль без PSRAM.
