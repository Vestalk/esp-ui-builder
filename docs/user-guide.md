# ESP UI Builder — посібник користувача

ESP UI Builder — програма, у якій екран для дисплея ESP32 збирається мишею, а на виході виходить
готовий код MicroPython: модуль на кожну сторінку з класом `UI`, драйвер дисплея, шрифти й картинки.
Код пишете лише ви — і лише те, що стосується вашого пристрою: звідки беруться значення (датчики,
мережа) і коли показувати яку сторінку.

## Швидкий старт: перший екран за 30 хвилин

### 1. Що потрібно (2 хв)
- Плата **ESP32-S3** (підійдуть також ESP32 і ESP32-C3), USB-кабель з передачею даних.
- Дисплей **GMT020-02-8B v1.21** (2.0", ST7789, 240×320, SPI).
- Комп'ютер з **VS Code** і розширенням **MicroPico** (або командою `mpremote`).
- ESP UI Builder: готова збірка для вашої системи (сторінка релізів) або з вихідного коду:
  `pip install .` у теці проєкту (Python ≥ 3.11).

### 2. Підключіть дисплей (5 хв)
Типова схема для ESP32-S3 (так налаштовано новий проєкт):

| Пін дисплея | ESP32-S3 |
|---|---|
| GND | GND |
| VCC | 3V3 |
| SCL | GPIO 12 |
| SDA | GPIO 11 |
| RES | GPIO 8 |
| DC | GPIO 9 |
| CS | GPIO 10 |
| BLK | GPIO 7 (якщо пін є) |

Інші піни можна вибрати в діалозі «Дисплей» — програма підкаже, які GPIO на вашому чипі зайняті
(USB, флеш) чи працюють лише на вхід. Докладніше — [`hardware.md`](hardware.md).

### 3. Прошийте MicroPython (5 хв)
Завантажте прошивку `ESP32_GENERIC_S3` з <https://micropython.org/download/ESP32_GENERIC_S3/>
(для плати з octal PSRAM — варіант `SPIRAM_OCT`) і запишіть її:

```sh
pip install esptool
esptool.py --chip esp32s3 --port <ПОРТ> erase_flash
esptool.py --chip esp32s3 --port <ПОРТ> write_flash -z 0 ESP32_GENERIC_S3-<версія>.bin
```

`<ПОРТ>` — наприклад `/dev/cu.usbmodem1101` (macOS), `/dev/ttyACM0` (Linux), `COM5` (Windows).

### 4. Зберіть екран (10 хв)
1. Запустіть програму (збірка — «ESP UI Builder»; з вихідного коду — `espui gui`). Відкрийте приклад **Файл → Відкрити… → `examples/weather.espui`**
   або почніть з порожньої сторінки.
2. Клацніть **«Дисплей…»** на панелі інструментів і перевірте чип, драйвер, орієнтацію й піни.
3. Додайте елементи з палітри зліва (клік — у центр, перетягування — у потрібне місце),
   тягніть їх мишею, міняйте розмір за маркери.
4. Праворуч — **Властивості** виділеного елемента, нижче — **Параметри** сторінки.
   Створіть параметр (**+ Параметр**), перетягніть його на елемент — елемент покаже значення.
5. Унизу, у **Тестових значеннях**, посувайте повзунки — прев'ю одразу показує, як це виглядатиме.
   Прев'ю малює той самий кадр, що й дисплей.

Проєкт зберігається сам (через 1,5 с після зміни); перший раз виберіть файл: **Файл → Зберегти як…**.

### 5. Згенеруйте й залийте (5 хв)
1. **▶ Згенерувати** → виберіть, **де** створити папку: програма створить у ній теку з назвою
   сторінки (наприклад `main/`) і покладе файли туди.
2. Відкрийте цю теку у VS Code, підключіть плату й виконайте команду MicroPico
   **«Upload project to Pico»** — завантажаться і `.py`, і картинки (`img/*.bin`).
3. Запустіть `main.py` (MicroPico: **Run**) — на екрані з'явиться ваша сторінка, а демо в `main.py`
   змінює перший числовий параметр і друкує час `update()`.

Готово. Далі — замініть демо в `main.py` своїм кодом (див. [Код на платі](#код-на-платі)).

## Дисплей
**Дисплей…** (кнопка на панелі або меню «Дисплей»):
- **Модель**:

  | Модель | Розмір | Контролер | Особливості |
  |---|---|---|---|
  | GMT020-02-8B v1.21 (2.0") | 240×320 | ST7789 | типова; інверсія увімкнена |
  | 3.5" IPS 480×320 | 320×480 | ILI9488 | через SPI лише 18-біт колір: 3 байти на піксель, перетворення скомпільоване (viper); повний екран — 300 КБ буфера, тож для «буфер на весь екран» потрібна PSRAM |
  | 1.28" круглий | 240×240 | GC9A01 | на полотні видно лише вписане коло, кути затінені |
  | **Свій розмір…** | 16…800 px | ST7789 / ILI9341 / ILI9488 / GC9A01 | див. нижче |

  **Свій розмір**: контролер, розмір у портреті, **зсув у пам'яті** контролера (потрібен, коли панель
  менша за неї: 135×240 ST7789 — 52 / 40; 240×240 ST7789 — 0 / 0, зсув для повороту 180°
  програма рахує сама), **порядок кольорів** (якщо червоний і синій переплутані — BGR / RGB) і
  «круглий». Програма перевіряє, що панель зі зсувом вміщується в пам'ять контролера.
- **Інверсія кольорів** — для будь-якої моделі: увімкніть, якщо на платі «негатив» (білий — чорний).
  За замовчуванням як у профілю: ST7789 і GC9A01 — так, ILI9488 / ILI9341 — ні.
- **Орієнтація** 0–3: 0/2 — портрет, 1/3 — альбом (розміри підписані для вибраного дисплея).
  Елементи, що після повороту опинились за межами екрана, показуються в рядку стану.
- **Частота SPI**: 20 / 40 / 80 МГц. 80 МГц — лише на пінах IOMUX (типова схема ESP32-S3 підходить).
- **Чип** (ESP32-S3, ESP32, ESP32-C3) і **драйвер**: вбудований (рекомендований: для ST7789 —
  `ui_st7789.py`, для ILI9488 / ILI9341 / GC9A01 — `ui_tft.py`) або `st7789py` (лише ST7789). Усі —
  чистий Python на стандартній прошивці; текст і картинки виглядають однаково.
- **Піни**: SCL, SDA, DC — обов'язкові; **RES, CS, BLK — можна лишити порожніми**, якщо на модулі
  їх немає (без CS шина працює в режимі SPI 3, як потрібно 7-піновим ST7789; без RES дисплей
  скидається командою); **MISO** — спільний для сенсора XPT2046 і SD-карти; поле з'являється, лише коли ввімкнено одне з них. Усі помилки показуються
  разом, «OK» стає доступним, коли їх немає.
- **Сенсорний екран** (за замовчуванням — немає): **XPT2046** (резистивний, на більшості 3.5"
  ILI9488) — на тій самій шині SPI: T_CLK → SCL, T_DIN → SDA, T_DO → MISO, свій T_CS і (за
  бажанням) T_IRQ; калібрування — сирі значення 0–4095 на краях екрана в портреті (поміняйте
  місцями, щоб віддзеркалити вісь; «осі переставлені» — якщо X і Y навпаки). **CST816S**
  (ємнісний, круглі GC9A01 з сенсором) — I2C: SDA, SCL, за бажанням INT і RST. На платі:
  `touch = ui_display.create_touch(display)`, `touch.read()` → `(x, y)` в координатах екрана
  поточної орієнтації або `None`.
- **SD-карта** (за замовчуванням вимкнена): слот microSD модуля на тій самій шині SPI (SD_SCK → SCL,
  SD_MOSI → SDA, SD_MISO → MISO) зі своїм SD_CS; картка FAT32. На платі:
  `ui_display.mount_sd(display)` монтує її в `/sd` (шлях можна змінити), далі звичайні
  `open("/sd/log.txt", "w")`, `os.listdir("/sd")`. Дисплей, сенсор і картка по черзі
  користуються однією шиною: кожен перемикає її на свою швидкість і повертає дисплейну.
- Увімкнений сенсор чи картка додає в згенеровану папку `ui_touch.py` / `ui_sd.py`, а приклад
  `main.py` показує, як їх використати.
- **Пам'ять** — як сторінка користується RAM плати; готові варіанти або «Своє»:

  | Варіант | Буфер області | Кеш картинок | Для яких плат |
  |---|---|---|---|
  | Без PSRAM (типово) | 16 КБ | вимкнено | ESP32, ESP32-C3, ESP32-S3 без PSRAM |
  | Без PSRAM, більше RAM | 32 КБ | вимкнено | ті самі, коли RAM лишається вільна |
  | PSRAM 2 МБ | весь екран (150 КБ) | 1 МБ | ESP32-S3R2, ESP32-WROVER |
  | PSRAM 8 МБ | весь екран (150 КБ) | 4 МБ | ESP32-S3 N16R8, N8R8 |

  **Буфер області** — скільки RAM на одну смугу області, що перемальовується. Якщо область більша
  за буфер, вона малюється смугами згори донизу, і на екрані видно, як вона «наповзає»; з буфером на
  весь екран кожна зміна з'являється одразу. **Кеш картинок** — картинки, прочитані з флешу один раз,
  лишаються в RAM, і перемальовування над ними в кілька разів швидше (на ESP32-S3 з PSRAM фон
  320×240 під елементом, що крутиться: ~160 → ~45 мс). Обидва значення пишуться в `ui_display.py`
  (`BUF_BYTES`, `IMAGE_CACHE`) і враховуються в оцінці RAM у рядку стану.

## Смуга прогресу і дуга
Обидві — шкали: значення заповнює нерухому **доріжку**. У властивостях:
- **Колір** — колір заповнення; **Доріжка** — колір доріжки (за замовчуванням `#23343f`);
- **Показувати доріжку** — вимкніть, і видно лише заповнену частину;
- **Показувати число** — вимкніть, щоб прибрати цифрове значення (у смуги лишається підпис з
  «Формат / текст»).

## Сторінки
- Вкладки над полотном — сторінки (`ui_<назва>.py · кількість елементів`). На полотні видно всі
  сторінки поруч; редагується активна (обведена).
- **+ Сторінка** — порожня або копія поточної. Подвійний клік — перейменувати (назва — ідентифікатор
  Python; `display`, `st7789`, `fonts` зайняті). **×** на вкладці: перший клік — «Видалити?», другий — видаляє.
- ←/→ на вкладках перемикають сторінки. Масштаб: −/+, клік по відсотках — 100 %, **Вмістити все**,
  Ctrl/⌘ + коліщатко.

## Елементи
Прямокутник, коло, лінія, текст, число, смуга прогресу, дуга, картинка, графік.
- **Мишею**: тягніть (сітка 4 px, з Alt — без неї), 8 маркерів — розмір, стрілки — 1 px, Shift — 10 px,
  Delete — видалити. Порожнє місце полотна — прокрутка.
- **Шари** (знизу): верхній рядок — над усіма. Порядок: перетягування рядка, кнопки ↑/↓,
  ↑/↓ у списку, Ctrl/⌘+↑/↓ з будь-якого місця.
- **Властивості**: id, тип (зміна підставляє розміри й знімає несумісну прив'язку з повідомленням),
  x/y/w/h, колір, «Дані з параметра» (лише сумісні), формат (`%s`, `%d`, `%.1f`, `%%`),
  шрифт і розмір. У властивостях — лише сталі значення; усе, що залежить від параметрів, — в «Умовах».
- Кожна дія скасовується (Ctrl/⌘+Z); перетягування — один крок.

## Параметри
Параметри — це дані, які ваш код передає екрану. Типи: `float`, `int`, `bool`, `str`, `enum`,
`series` (список точок `{x: y}` для графіка).
- **+ Параметр** — назва, тип, межі, варіанти, макс. довжина/точок, значення за замовчуванням;
  помилки показуються біля поля.
- **✎** — редагування: перейменування оновлює всі посилання, нові межі обмежують тестове значення,
  зміна типу прибирає несумісне (з підсумком у рядку стану). **×** — видалити разом з усіма посиланнями.
- **Перетягування параметра**: на сумісний елемент — прив'язка; `bool` на будь-який елемент —
  умова «сховати, коли false»; на вільне місце — новий елемент (число, текст або графік).
- **Тестові значення** — лише для прев'ю: повзунок, прапорець, список, поле `x:y; x:y` з «↻ випадкові».
- **Параметри в коді** — блок `DEFAULTS` саме таким, яким його згенерує програма.
- Для `str` можна вибрати, які символи знадобляться на платі (латиниця + українська, латиниця, цифри)
  і додати свої — у шрифти потрапляють лише вони.

## Умови й залежності
Блок **«Умови»** у властивостях — єдине місце, де вигляд залежить від параметрів.
- **Умова**: «якщо `<параметр> <оператор> <значення>` → `<властивість>` = `<значення>`»; властивості —
  колір, текст/формат, видимість, непрозорість, кут, x, y. Умова, що зараз спрацьовує, підсвічена;
  якщо спрацьовують кілька — перемагає нижня.
- **Оператори**: для чисел — `>`, `<`, `≥`, `≤`, `=`, `≠`, **у діапазоні** і **поза діапазоном**;
  для тексту й списку — `=`, `≠`; для bool — `=`. Діапазон задається двома полями «від … до …»,
  обидві межі входять: «температура у діапазоні 18…25» спрацьовує і при 18, і при 25. У файлі
  проєкту це `["temperature", "in", [18, 25]]` (`"not in"` — поза діапазоном).
- **Залежність**: «від `<числового параметра>` → `<властивість>`: при мін `a`, при макс `b`» —
  плавна зміна непрозорості, кута чи позиції.
- Поле властивості, якою керує умова, у «Властивостях» вимикається з підказкою, хто ним керує.
- Схований умовою елемент на платі не малюється; на полотні активної сторінки лишається тонка рамка.

## Прозорість, поворот, позиція
- **Вигляд**: непрозорість 0–100 % (і «Застосувати до всіх»), кут −180…180° (не для графіка),
  точка повороту — пресет або власна; її можна тягнути червоним хрестиком на полотні.
- Залежності x/y показують на полотні жовті рамки «мін»/«макс». Перетягування елемента чи стрілки
  зсувають базову позицію й усі x/y в умовах і залежностях разом.
- На платі: прозорість — змішування з тим, що під елементом; поворот прямокутників, ліній, смуг і дуг —
  швидкий, тексту — попіксельний (для великого тексту з кутом від параметра генератор попередить).
  Картинки теж повертаються (і анімації): повернута картинка читається в RAM цілком — з кешу
  картинок («Дисплей» → «Пам'ять»), якщо він увімкнений, інакше щоразу з флешу; копіювання з
  поворотом скомпільоване (viper), тож на ESP32 це швидко.

## Шрифти
Три вбудовані шрифти з повною українською абеткою: **Literata** (з засічками, за замовчуванням),
**JetBrains Mono** (моноширинний), **Press Start 2P** (піксельний, найчіткіший на 8/16/24 px).
Розмір 8–72 px. У `ui_fonts.py` потрапляють лише потрібні символи потрібних розмірів — генератор
показує обсяг («Шрифти: Literata 12/16/40 px — ui_fonts.py 18,4 КБ»). Символ, якого немає в шрифті,
стає «?», а генератор попереджає.

## Картинки й анімації
- **Статична картинка**: «Файл» — бібліотека картинок проєкту, «+ Файл…» додає PNG, JPG, WebP, GIF
  або відео (MP4, WebM; для відео потрібен пакет `av`). Оригінали зберігаються у файлі проєкту.
  Вписування: повністю / з обрізанням / розтягнути, «Розмір як у картинки».
- **Картинка з параметра** (`str`): «Картинки на платі (/img)» — клік ставить шлях тестовим значенням;
  на платі шлях передає ваш код (`ui.set_weather_icon("/img/rain.bin")`).
- **Анімація** (GIF/відео): до 48 кадрів, «⟳ Цикл» або «→ Один раз», «Кадр, мс». На платі грає
  `ui.tick()`, не блокуючи головний цикл; `ui.play_<id>()` — з початку.
- Генерація конвертує все сама: `img/<назва>.bin` (RGB565 під розмір елемента) і папки кадрів
  `img/<назва>/000.bin…` з `anim.json`. Нічого конвертувати чи копіювати вручну не треба.

## Графік
Параметр `series` — список точок `[{0: 14}, {3: 13}]`; ключ X — число або мітка до 7 символів.
Вигляд: лінія, лінія з точками, стовпці; підписи осей; межі Y (порожньо — авто: межі параметра,
розширені до даних); сітка. Порожній список — «немає даних».

## Генерація
**▶ Згенерувати** (Ctrl/⌘+G): файли пишуться в теку з назвою сторінки (для кількох сторінок —
з назвою файлу проєкту) всередині вибраної папки; вибрана папка запам'ятовується для проєкту; спершу проєкт перевіряється
(помилки показуються списком), потім пишуться файли й відкривається вікно результату з розмірами
й переглядом. Рядок стану весь час показує оцінку пам'яті: флеш (код + шрифти + картинки) і RAM
(буфер області малювання, гліфи, рядок картинки, кеш картинок).

| Файл | Що це |
|---|---|
| `ui_display.py` | піни, SPI, орієнтація, пам'ять (`BUF_BYTES`, `IMAGE_CACHE`) і `create()` для вибраного драйвера |
| `ui_st7789.py` або `st7789py.py` | драйвер дисплея (Python) |
| `ui_draw.py` | рушій: малювання областями, `update()`, анімації |
| `ui_fonts.py` | гліфи всіх сторінок |
| `ui_<сторінка>.py` | `DEFAULTS` і клас `UI` сторінки |
| `main.py` | приклад; **наступна генерація в ту саму папку його перезапише** — свій код тримайте окремо |
| `__init__.py` | робить теку сторінки пакетом: `from ui.main import ui_display, ui_main` з будь-якого місця плати |
| `img/` | картинки й кадри анімацій |
| `.vscode/settings.json` | MicroPico завантажує й `.bin` |

## Код на платі
```python
import ui_display, ui_main

ui = ui_main.UI(ui_display.create())
p = dict(ui_main.DEFAULTS)     # усі параметри зі значеннями за замовчуванням
ui.draw(p)                     # повна перемальовка

while True:
    p["temperature"] = read_sensor()   # ваш код
    ui.update(p)               # перемальовує лише змінене
    ui.tick()                  # анімації (якщо є)
```

**Сторінка в окремій теці.** Згенеровану теку можна покласти на плату будь-куди, наприклад
`/ui/main`, і підключити зі свого `main.py` у корені як пакет. Тека сама додає себе в `sys.path`
і знаходить свої картинки (`img/` поруч), нічого налаштовувати не треба:

```python
from ui.main import ui_display, ui_main

ui = ui_main.UI(ui_display.create())
```
- `ui.set_<параметр>(значення)` — змінити один параметр і одразу оновити екран.
- Кілька сторінок: `main.py` містить `pages` і `show(name)` — після перемикання завжди `draw()`.
- `series`: `p["history"].append({24: 18.5})` — `update()` помітить і зміну списку.

## Завантаження на плату
**MicroPico** (VS Code): відкрийте згенеровану папку → **Upload project to Pico** → **Run** для `main.py`.
`.vscode/settings.json` вже додає `bin` до типів файлів, які завантажуються.

**mpremote**:
```sh
cd my_screen
mpremote cp *.py :            # код у корінь плати
mpremote cp -r img :          # картинки, якщо папка img/ є
mpremote run main.py
```

## Командний рядок
```sh
espui gui [project.espui]                      # програма
espui generate project.espui -o out/           # усі сторінки
espui generate project.espui -o out/ --page main
```

## Якщо щось не так
- **Чорний екран**: перевірте піни в «Дисплеї» й живлення 3V3; спробуйте 20 МГц; запустіть
  `tools/hw_smoke.py` (червоний → зелений → синій → чорний).
- **Кольори інвертовані** або зображення дзеркальне — інший модуль дисплея; повідомте модель.
- **«?» замість літер** — символ не потрапив у шрифт: для `str`-параметра додайте символи в
  «Ще символи» діалогу параметра.
- **Сірий прямокутник замість картинки** — файлу немає на платі або він іншого розміру: перегенеруйте
  й завантажте `img/` (MicroPico — «Upload project»).
- **Мало пам'яті** (`MemoryError`) — дивіться оцінку в рядку стану: зменште великі анімації,
  кількість розмірів шрифтів, буфер області й кеш картинок у діалозі «Дисплей» → «Пам'ять»;
  плата з PSRAM дає набагато більше RAM.
- **Незбережений проєкт після збою** — при наступному запуску програма запропонує відновити чернетку.
