# Етап 00 — Підготовка середовища і заліза

**Мета:** мати репозиторій з інструментами якості й плату ESP32-S3 з MicroPython, на якій дисплей GMT020-02-8B
гарантовано працює. Без цього жоден наступний етап не можна перевірити.

**Залежить від:** —
**Оцінка:** 2–3 дні

## Результат
- Каркас проєкту на Python з CI.
- Плата з MicroPython, підключена через MicroPico (і запасний шлях `mpremote`).
- Записані реальні піни підключення дисплея.
- Тестовий скрипт, що заливає екран кольором.

## Задачі

### Репозиторій
- [ ] `pyproject.toml` (Python ≥ 3.11), пакет `src/espui`, точка входу `espui`.
- [ ] ruff, mypy (strict для `core/` і `generators/`), pytest, pre-commit.
- [ ] GitHub Actions: lint + typecheck + тести на Linux/Windows/macOS.
- [ ] Збірка unix-порту MicroPython у CI (або кешований бінарник) для тестів етапу 03+.
- [ ] Папки `tests/unit`, `tests/mpy`, `tests/gui`, `examples/`.

### Залізо
- [ ] Прошити ESP32-S3 стандартною прошивкою `ESP32_GENERIC_S3` (з PSRAM, якщо модуль її має).
      Власні збірки MicroPython не потрібні: усі драйвери — Python-файли.
- [ ] Налаштувати MicroPico у VS Code: Configure Project, Switch Stubs → ESP32.
- [ ] Перевірити завантаження файлів і REPL через MicroPico; якщо нестабільно — `mpremote`.
- [ ] Підключити GMT020-02-8B, записати піни у `docs/hardware.md`: SCL(SCK), SDA(MOSI), RES, DC, CS, BLK.
- [ ] Перевірити, чи є на модулі пін BLK (у частини модулів серії лише 7 пінів).
- [ ] Не використовувати GPIO19/20 (USB) і пін-стрепи.

### Перевірочний скрипт
- [ ] `tools/hw_smoke.py`: ініціалізує ST7789 найпростішим способом (`machine.SPI`, послідовність команд),
      заливає екран червоним, зеленим, синім по черзі.

## Критерії готовності
- [ ] CI зелений на порожньому пакеті.
- [ ] `hw_smoke.py`, завантажений через MicroPico, показує три кольори без артефактів.
- [ ] `docs/hardware.md` містить фото/схему підключення, піни, наявність BLK, версію MicroPython.
