# Етап 04 — Умови: дискретні зміни від параметрів

**Мета:** елементи змінюють вигляд залежно від параметрів без коду з боку розробника.
**Принцип:** усе, що залежить від параметрів, задається лише в блоці «Умови» (`rules[]`); у властивостях — тільки базові значення.
Цей етап — записи-умови (`condition`); плавні залежності (`mapping`) — етап 05.

**Залежить від:** 03
**Оцінка:** 3–4 дні

## Специфікація

### Умова (`condition`)
- «якщо `<параметр> <оператор> <значення>` → `<властивість>` = `<значення>`».
- Властивості: колір, текст/формат (лише текст і число), видимість (показати/сховати), непрозорість %, кут °
  (не для графіка), x, y.
- Оператори: bool `=`; enum/str `=`, `≠`; float/int `>`, `<`, `≥`, `≤`, `=`, `≠`.
- Застосовуються після залежностей, зверху вниз; нижня умова, що спрацювала, перемагає.
- `series` в умовах не використовується.
- Показ за bool — звичайна умова «якщо `alarm` = false → сховати»; схований елемент очищує свою область
  (з перемальовкою того, що під ним).

### Генерація
```python
def _draw_alarm_lbl(self, p):
    # перемальовується, коли змінюється: alarm
    color = 0xFA4A
    visible = True
    # умови (нижня перемагає)
    if not p['alarm']:
        visible = False
    if p['status'] == 'Помилка':
        color = 0xE923
    if not visible:
        return self._clear(200, 188, 110, 22)
    ...
```
- Залежності елемента = `bind` + параметри всіх записів `rules[]`.

## Критерії готовності
- [ ] Приклад з `alarm` (напис «ПЕРЕГРІВ» видно лише при `alarm = True`, температура червоніє) працює на платі.
- [ ] Видалення параметра прибирає всі записи `rules[]`, що на нього посилаються.

## Тести
- `core.evaluate`: таблиця «значення параметрів → колір, текст, видимість».
- Генератор: snapshot і запуск на unix-порті з перевіркою кадру для кожної комбінації `alarm`/`status`.
